# TacticAI Full Implementation Design Specification

## 1. システム概要
本プロジェクトは、Google DeepMindの "TacticAI" [1] を再現・拡張し、サッカーのコーナーキック（CK）における戦術分析システムを構築する。
モデルは幾何学的深層学習（GDL）を基盤とし、以下の**4つの主要タスク**を統合的に処理する。

### 4つの主要タスク
1.  **Receiver Prediction (受け手予測):** CK後に最初にボールに触れる選手を予測（Node Classification）。
2.  **Shot Prediction (シュート予測):** そのCKからシュートが発生するかを予測（Graph Classification / Conditional）。
3.  **Similar CK Retrieval (類似CK検索):** 幾何学的潜在空間における表現ベクトルを用いて、戦術的に類似した過去のCKを検索する。
4.  **Guided Generation (戦術生成):** 特定の結果（シュート確率の増減など）を条件として、選手の最適な配置・動きを生成する（CVAE）。

---

## 2. 共通アーキテクチャ (Base Encoder)

全てのタスクは、ピッチの対称性を考慮した共通のグラフエンコーダの出力を利用する。

### 2.1 入力データ定義
* **グラフ構造:** 完全グラフ ($N=22$)。
* **対称性 ($D_2$ Group):** ピッチの `(Identity, Horizontal Flip, Vertical Flip, Both)` の4ビューを入力として生成し、幾何学的等価性を保証する。

### 2.2 エンコーダ (GATv2 Group Convolution)
* **バックボーン:** $D_2$ Group Convolution + GATv2。
* **出力 ($H$):**
    * 形状: `[Batch, 4 (Views), N, Hidden_Dim]`
    * この潜在表現が全てのダウンストリームタスクの入力となる。

## 3. タスク別ヘッド設計詳細

### 3.1 Receiver Prediction Head (受け手予測)
* **タスク:** 22人の選手の中からボール受取人を特定する多クラス分類。
* **入力処理:**
    * エンコーダ出力 $H$ をビュー方向で平均化（Group Averaging）し、不変表現 $H_{inv}$ `[Batch, N, Dim]` を作成。
* **ネットワーク:**
    * `Linear` -> `LogSoftmax`
* **出力:** 受取人確率分布 $P(\text{receiver})$。形状 `[Batch, N]`。
* **Loss:** Cross Entropy Loss。

### 3.2 Shot Prediction Head (シュート予測)
単純な二値分類ではなく、受け手予測の確率を利用した条件付き確率の総和としてモデル化する（論文の手法）。

* **数理モデル:**
    $$P(\text{shot}) = \sum_{i=1}^{22} P(\text{shot} | \text{receiver}=i) \cdot P(\text{receiver}=i)$$
* **入力:**
    * 不変ノード表現 $H_{inv}$ `[Batch, N, Dim]`（バックボーンからのノード埋め込み）。
    * `receiver_probs`: Task 3.1 の出力確率 `[Batch, N]`。
        * **学習時**: Pretrained Receiverモデルから取得（凍結）、またはGT receiver（one-hot分布）
        * **推論時**: Pretrained Receiverモデルから予測確率分布を取得
* **ネットワーク:**
    * **Conditional MLP:** 各選手 $i$ のノード埋め込み $h_i$ に対して、その選手が受け手だった場合のシュート確率を計算するMLP。
        * `MLP(h_i) -> s_i` (Scalar logit) → `[Batch, N]`
    * **Aggregation:** 各選手のシュート確率 $\sigma(s_i)$ とReceiver確率 $p_i$ の重み付き和を計算。
        * $\sum_i \sigma(s_i) \times p_i$ → `[Batch, 1]` (最終的なシュート確率logit)
* **Loss:** Binary Cross Entropy Loss。
* **バックボーン:**
    * Pretrained Receiverモデルのバックボーンを使用（Fine-tuning、凍結しない）
    * D2等変性の設定はReceiver予測と同じ（設定ファイルから読み込み）
    * Readout: `None`（ノード埋め込み `[Batch, N, Dim]` をそのまま出力）

### 3.3 Retrieval System (類似CK検索)
学習可能なヘッドではなく、学習済みエンコーダの潜在空間を利用した検索モジュール。

* **入力:**
    * エンコーダ出力 $H$。
* **表現ベクトル生成 (Embedding Strategy):**
    1.  **Group Averaging:** 4つのビューを平均し、不変表現 $H_{inv}$ `[Batch, N, Dim]` を得る。
    2.  **Graph Pooling:** 選手方向（Node次元）で平均化（Mean Pooling）し、グラフ全体の表現ベクトル $z_{graph}$ `[Batch, Dim]` を得る。
        $$z_{graph} = \frac{1}{N} \sum_{i=1}^{N} H_{inv}[i]$$
* **検索ロジック:**
    * クエリCKのベクトル $q$ と、データベース内の過去CKベクトル $k$ との**コサイン類似度**を計算。
    * $\text{Similarity}(q, k) = \frac{q \cdot k}{\|q\| \|k\|}$
* **実装要件:**
    * 推論時に全学習データの埋め込みを事前に計算・保存する `Index` クラスが必要。

### 3.4 Guided Generation Head (戦術生成: CVAE)
特定の条件（シュート成功/失敗）に基づいて、選手の位置・速度の調整案を生成する。

* **モデル:** Conditional VAE。
* **対称性:** 出力（座標）は反転に追従する必要があるため、**等変性（Equivariance）**を維持する。Group Averagingは行わず、Identity View（標準視点）の特徴量のみを使用する。
* **入力:**
    * `x_real`: 実際の配置 `[Batch, N, 4]` (x, y, vx, vy)。
    * `condition`: ターゲットとする結果 `[Batch, 1]`。
    * `z_enc`: エンコーダのIdentity View出力 `[Batch, N, Dim]`。
* **構成:**
    * **Prior Network:** $p(z|c)$ (通常は標準正規分布だが、ここでは条件付き学習)。
    * **Inference Network (Encoder):** $q(z | x, c, z_{enc})$
    * **Generation Network (Decoder):** $p(x | z, c, z_{enc})$
* **Loss:** MSE (再構成) + KL Divergence。

## 4. 実装詳細（Shot Prediction）

### 4.1 Pretrainedバックボーンのロード
* Receiver予測で学習したバックボーン（`checkpoints/receiver/backbone_d2.ckpt` または `backbone_no_d2.ckpt`）をロード
* バックボーンはFine-tuning（凍結しない）。必要に応じてバックボーンとヘッドで異なる学習率を設定

### 4.2 Receiver確率の取得
* **Pretrained Receiverモデル**: `checkpoints/receiver/best.ckpt` からReceiverHeadをロード（凍結）
* 学習時: Pretrained Receiverモデルから確率分布を取得、またはGT receiver（one-hot）
* 推論時: Pretrained Receiverモデルから予測確率分布を取得

### 4.3 実装クラス
* **ShotHeadNodeBased**: ノード埋め込み `[Batch, N, Dim]` を入力として、各選手に対するシュート確率logitを出力
* 既存の`ShotHeadNodeBased`クラスを活用
