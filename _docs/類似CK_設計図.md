# 類似CK検索システム設計図

## 1. システム概要

類似CK検索システムは、学習済みエンコーダの潜在空間を利用して、戦術的に類似した過去のコーナーキック（CK）を検索するシステムである。検索システムと可視化システムの2つのコンポーネントで構成される。

- **検索システム**: 埋め込みベクトルを生成し、コサイン類似度に基づいて類似CKを検索
- **可視化システム**: 検索結果を視覚的に確認・評価するためのWebアプリケーション

---

## 2. 検索システム (Retrieval System)

### 2.1 概要

学習可能なヘッドではなく、学習済みエンコーダ（Receiver Predictionモデルのバックボーン）の潜在空間を利用した検索モジュール。

### 2.2 入力

- **エンコーダ出力**: $H$ `[Batch, 4 (Views), N, Hidden_Dim]`
  - Receiver Predictionモデルのバックボーン（GATv2Network or GATv2Network4View）から取得
  - D2等変性が有効な場合、4ビュー（Identity, Horizontal Flip, Vertical Flip, Both）の出力

### 2.3 表現ベクトル生成 (Embedding Strategy)

1. **Group Averaging**: 4つのビューを平均し、不変表現 $H_{inv}$ `[Batch, N, Dim]` を得る。
   ```python
   H_inv = H.mean(dim=1)  # [Batch, N, Hidden_Dim]
   ```

2. **Graph Pooling**: 選手方向（Node次元）で平均化（Mean Pooling）し、グラフ全体の表現ベクトル $z_{graph}$ `[Batch, Dim]` を得る。
   $$z_{graph} = \frac{1}{N} \sum_{i=1}^{N} H_{inv}[i]$$
   ```python
   z_graph = H_inv.mean(dim=1)  # [Batch, Hidden_Dim]
   ```

### 2.4 検索ロジック

- **類似度計算**: クエリCKのベクトル $q$ と、データベース内の過去CKベクトル $k$ との**コサイン類似度**を計算。
  $$\text{Similarity}(q, k) = \frac{q \cdot k}{\|q\| \|k\|}$$
  
- **Top-k検索**: 類似度が高い順にTop-$k$ の類似CKを返す。

### 2.5 実装要件

- **Indexクラス**: 推論時に全学習データの埋め込みを事前に計算・保存するクラスが必要
  - 埋め込みベクトルの保存形式: NumPy配列またはFaissインデックス
  - メタデータ（元のデータID、ファイルパスなど）の保存
  - 効率的な検索のためのインデックス構築

- **バックボーンのロード**: 
  - Pretrained Receiverモデルからバックボーンをロード
  - D2有無に応じて `backbone_d2.ckpt` または `backbone_no_d2.ckpt` を使用

## 3. 可視化システム (Visualization System)

### 3.1 目的

- 検索された類似CKの戦術パターンを視覚的に確認・評価する
- ボールの軌跡、選手の配置、選手の速度ベクトルを同時に可視化する
- 類似CK検索の定性評価を支援する

### 3.2 技術スタック

- **言語**: Python 3.9+
- **フレームワーク**: Streamlit (Web UI用)
- **可視化ライブラリ**: Plotly Graph Objects (インタラクティブな操作、アニメーション、レイヤー重ね合わせのため)
- **データ処理**: Pandas, NumPy

### 3.3 入力データ構造

可視化システムは以下のカラムを持つCSVデータを読み込む（またはPickleファイルから変換）：

- `frame_id`: タイムスタンプ（連番）
- `player_id`: 選手ID（ボールの場合は 'ball'）
- `team_id`: チームID（0: 守備, 1: 攻撃, -1: ボール）
- `x`: x座標 (メートル, -52.5 ~ 52.5)
- `y`: y座標 (メートル, -34 ~ 34)
- `vx`: x方向の速度ベクトル
- `vy`: y方向の速度ベクトル

### 3.4 機能要件

#### A. サッカーコートの描画 (背景)

- Plotlyの `layout.shapes` を使用して、緑色のピッチを描画する
- 以下のラインを白線で引くこと：
  - タッチライン、ゴールライン (105m x 68m想定)
  - ペナルティエリア、ゴールエリア
  - センターサークル、センターライン
  - **重要**: コーナーアーク（CKの分析なので必須）
  - ゴールポストの位置

#### B. データのプロット

1. **選手 (Scatter Plot)**:
   - 攻撃側と守備側で色を分ける（例: 赤 vs 青）
   - マーカーのサイズは適度な大きさにする
   - ホバー時に `player_id` などの情報を表示する

2. **ボールの軌跡 (Line Plot)**:
   - ボールの全フレームの座標 (`x`, `y`) を繋いで一本の線として描画する
   - 始点から終点に向かって色が変化する、または目立つ色（黄色やオレンジ）にする
   - 現在のフレームのボール位置には大きめのマーカーを表示する

3. **速度ベクトル (Quiver Plot / Arrow)**:
   - 各選手の位置 `(x, y)` から `(x + vx, y + vy)` に向かって矢印を描画する
   - `plotly.figure_factory.create_quiver` または `go.Scatter` と `layout.annotations` (矢印) を使用する
   - 矢印の長さはスケーリング係数（例: 0.5倍など）で調整可能にする
   - 選手から進行方向へ矢印が伸びるスタイルを目指す

#### C. UI / インタラクション

- **スライダー**: `frame_id` を選択するスライダーを設置。スライダーを動かすと、その瞬間の選手位置とベクトルが更新される（ボール軌跡は常に全軌跡を表示しておくか、現在時点までを表示するオプションがあると良い）

- **サイドバー**:
  - 表示オプション（ベクトルの表示ON/OFF、ID表示ON/OFF）
  - クエリCKと類似CKの選択
  - 類似度の表示
  - 複数の類似CKを並べて表示する機能（2列、4列など）

### 3.5 座標系

- ピッチ中心を(0,0)とする標準的なトラッキングデータ形式に合わせる
- x軸: -52.5 ~ 52.5 (メートル)
- y軸: -34 ~ 34 (メートル)

### 3.6 出力ファイル構成

```
tacticai/retrieval/visualization/
├── app.py              # メインアプリケーションコード
├── utils.py            # コート描画関数、データロード関数
├── requirements.txt    # 必要なライブラリ（Streamlit, Plotly, Pandas, NumPy）
└── README.md           # 実行方法の説明
```

### 3.7 実装の注意点

- ベクトルが見にくくならないよう、矢印のスタイル（head_size等）を調整する
- パフォーマンスを考慮し、大量のデータでも快適に動作するようにする
- 検索システムから取得した類似度情報を適切に表示する

## 4. 統合アーキテクチャ

### 4.1 ワークフロー

1. **インデックス構築フェーズ**:
   - 全学習データに対してPretrained Receiverモデルのバックボーンを実行
   - 各CKから埋め込みベクトル $z_{graph}$ を生成
   - インデックスに保存（メタデータと一緒に）

2. **検索フェーズ**:
   - クエリCKに対して同様に埋め込みベクトルを生成
   - インデックス内の全ベクトルとコサイン類似度を計算
   - Top-k類似CKを返す

3. **可視化フェーズ**:
   - 検索結果（クエリCKとTop-k類似CK）を可視化アプリケーションに渡す
   - 各CKのトラッキングデータを読み込み、コート上に描画
   - ユーザーがインタラクティブに確認・評価

### 4.2 ファイル構成

```
tacticai/
├── retrieval/
│   ├── index.py         # Index class for embedding storage
│   ├── search.py        # Search logic implementation
│   └── visualization/   # Visualization system
│       ├── app.py       # Streamlit main application
│       ├── utils.py     # Court drawing, data loading functions
│       └── requirements.txt
└── ...
```
