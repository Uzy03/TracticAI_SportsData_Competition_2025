# 類似CK検索：改善まとめ（2026-01-04）

## 目的

「CKの位置（4象限）だけ」で似ている/似ていないが決まるのではなく、**戦術（選手配置の構造）として似ているCK**を、位置が違っても拾える状態に近づける。

## 変更点（実装）

### 1) cos類似度：攻撃/守備の表現を分離して類似度計算

- **従来**: ノード埋め込みを単純平均してグラフ埋め込み1本 → 攻守が混ざる
- **改善**: ノード特徴 `team_id`（0=攻撃,1=守備）で
  - `z_att`（攻撃ノード平均）
  - `z_def`（守備ノード平均）
  を作り、類似度を **`w_att*cos(z_att) + w_def*cos(z_def)`** で合成
- **影響**: 「攻撃の形が似てる / 守備の形が似てる」を分けて比較でき、混ざり由来の誤差を軽減

### 2) 4つのCK位置（左右/上下）の“角反転正規化”

- **狙い**: 角の違い（4象限）そのものが類似度を支配するのを弱める
- **適用先**:
  - cos類似度（埋め込み生成時）
  - 提案手法（構造類似度/Hungarian）計算時

### 3) 可視化の修正（破綻ケース対策）

- `idx193` のように、ボール（キッカー）が **コーナー固定のプレースホルダ**になって「反対側から蹴ってる」ように見えるケースを、`kicker_idx` 優先で補正
- 矢印が「線だけ」になる（先端が見えない）ケースを減らすため、矢印の座標をクランプし、ゼロ長矢印をスキップ

## 定性的な観察（添付スクリーンショットの結果）

スクリーンショット上の検索結果を確認すると、

- **cos類似度**: Top-k が主に **同じCK位置（同一象限）**のサンプルに偏る傾向
- **提案手法（構造類似度）**: Top-k に **別のCK位置（別象限）**のサンプルもランクイン

このことから、提案手法は少なくとも定性的には、
**「位置座標だけ」ではなく「配置の構造（戦術）」を比較できている可能性が高い**。

※注意：これは可視化結果からの定性的評価であり、厳密には同一条件での定量評価（例：戦術ラベル/クラスタ等）も今後検討余地あり。

## 再現方法（コマンド）

### インデックス再構築（cos用：必須）

```bash
# consistency_stable
python scripts/build_retrieval_index_my_method.py \
  --config configs_my_method/multitask_receiver_shot_d2_consistency_stable.yaml

# baseline_stable
python scripts/build_retrieval_index_my_method.py \
  --config configs_my_method/multitask_receiver_shot_d2_baseline_stable.yaml
```

### 可視化（Streamlit）

```bash
python -m streamlit run my_method/retrieval/visualization/app.py
```

- Streamlit側で挙動が更新されない場合は、サイドバーの **「♻️ キャッシュクリア」** か、アプリ再起動を行う。
