# Receiver予測モデルの長期学習による性能限界の検証

## 目的

Receiver予測モデルを200エポックまで学習させ、以下の点を検証する：

1. **性能の収束点**: どのエポックで性能が頭打ちになるか
2. **過学習の有無**: 学習精度とテスト精度の乖離がどの程度か
3. **D2有効/無効での長期学習での性能差**: D2等変性が長期学習でどの程度の効果があるか
4. **学習の安定性**: 50エポック以降も安定して学習が継続するか（特にD2有効時）

## 背景

現在、50エポックでの学習結果では以下のことが確認されている：

- **D2有効**: Test Acc=0.2632, Test Top-3=0.4386
- **D2無効**: Test Acc=0.2632, Test Top-3=0.4561

50エポックでは性能がまだ向上する可能性があり、より長期の学習で性能の限界を確認する必要がある。

また、D2有効時はエポック38でモデル崩壊が発生したが、学習率と勾配クリッピングの調整により改善されている。200エポックでの長期学習でも安定性を確認する必要がある。

## 実験設定

### D2有効

- **設定ファイル**: `configs/receiver_full_simplified.yaml`
- **エポック数**: 200
- **学習率**: 0.0005（D2有効時の安定化のため0.001から下げた）
- **勾配クリッピング**: enabled=true, max_norm=0.5（安定化のため1.0から下げた）
- **その他**: 既存の設定を維持

### D2無効

- **設定ファイル**: `configs/receiver_full_simplified.yaml`（`d2.enabled: false`に変更）
- **エポック数**: 200
- **学習率**: 0.001（D2無効時は通常の学習率で問題なし）
- **勾配クリッピング**: enabled=true, max_norm=1.0
- **その他**: 既存の設定を維持

## 確認項目

### 1. 性能の収束

- 各エポックでの学習精度・テスト精度の推移
- 性能が頭打ちになるエポックの特定
- 最終的な性能の比較

### 2. 過学習の検出

- 学習精度とテスト精度の乖離
- 学習損失とテスト損失の比較
- Early stoppingが適切に機能するか

### 3. D2有効/無効の比較

- 最終的なテスト精度の比較
- 学習曲線の比較
- D2等変性の長期学習での効果

### 4. 安定性の確認

- D2有効時も200エポック完走できるか
- モデル崩壊が発生しないか
- 勾配クリッピングの効果

## 期待される結果

### 最良ケース

- 両方とも200エポック完走
- 性能がさらに向上（Test Acc > 0.27など）
- 過学習なし（学習精度とテスト精度の乖離が小さい）
- D2有効時の方が性能が高い

### 現実的なケース

- 性能は100-150エポック付近で頭打ち
- ある程度の過学習が発生（学習精度 > テスト精度）
- D2有効/無効で性能差は限定的

### 問題が発生する場合

- D2有効時でモデル崩壊が再発
- 過学習が大きすぎる（学習精度 >> テスト精度）
- 性能が悪化する

## 実装・実行手順

### 1. D2有効での学習

```bash
# 設定確認: d2.enabled: true, lr: 0.0005, max_norm: 0.5, epochs: 200
python tacticai/train/train_receiver.py --config configs/receiver_full_simplified.yaml
```

### 2. D2無効での学習

```yaml
# configs/receiver_full_simplified.yaml で d2.enabled: false に変更
# 学習率と勾配クリッピングは通常設定に戻す
```

```bash
python tacticai/train/train_receiver.py --config configs/receiver_full_simplified.yaml
```

### 3. 結果の比較

- 学習曲線のプロット
- 最終性能の比較
- 収束点の特定

## 優先度

**中** - 性能の限界を理解するために有用だが、即座に必要ではない

## 補足

- 200エポックの学習には時間がかかるため、実行前に十分な時間を確保すること
- 必要に応じて、early stoppingの設定を調整すること
- 学習中にモデル崩壊が発生した場合は、さらに学習率や勾配クリッピングを調整すること
