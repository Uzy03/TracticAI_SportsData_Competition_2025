# コマンド一覧

TacticAIプロジェクトで使用する主要なコマンドの一覧です。

## 受け手予測（Receiver Prediction）

### 学習

```bash
# 基本コマンド（D2等変性無効）
python tacticai/train/train_receiver.py --config configs/receiver_full_simplified.yaml

# D2等変性有効版（設定ファイルで d2.enabled: true に設定）
python tacticai/train/train_receiver.py --config configs/receiver_full_simplified.yaml

# デバッグ用（過学習確認）
python tacticai/train/train_receiver.py --config configs/receiver_full_simplified.yaml --debug-overfit
```

### 設定ファイル

- `configs/receiver_full_simplified.yaml`: メイン設定ファイル
- `configs/receiver_full_simplified_200epoch_d2.yaml`: 200エポック学習用（D2有効）

### 出力

- ログファイル: `runs/training_{timestamp}.log`
- 学習履歴: `runs/training_history_{timestamp}.csv`
- ベストモデル: `checkpoints/receiver/best.ckpt`
- バックボーン: `checkpoints/receiver/backbone_d2.ckpt` または `backbone_no_d2.ckpt`

## マルチタスク学習（Multi-task Learning: Receiver + Shot）

受け手予測（ノードレベル）とシュート予測（グラフレベル）を同時に学習するマルチタスク学習です。共有バックボーンを使用して、埋め込みの多様性を向上させることを目的としています。

### 学習

```bash
# D2等変性無効版
python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_no_d2.yaml

# D2等変性有効版
python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_d2.yaml

# オーバーフィットテスト（少数サンプルで train=val=test を同一にして健全性確認）
# ※損失が下がらない/精度が上がらない場合は実装 or ラベル整合性を疑う
python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_no_d2_overfit.yaml
python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_d2_overfit.yaml

# オーバーフィットテスト（8サンプル版）
python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_no_d2_overfit8.yaml
python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_d2_overfit8.yaml

# バックグラウンド実行（tmux使用）
tmux new-session -d -s train_multitask_no_d2 'python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_no_d2.yaml'
tmux new-session -d -s train_multitask_d2 'python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_d2.yaml'

# GPUの空き待ちしてから実行（tmux使用）
# 例: GPU0の空きVRAMが 8000MiB 以上になるまで待ってから学習開始
tmux new-session -d -s wait_train_multitask_d2 \
  "bash -lc 'scripts/wait_for_gpu.sh --gpu 0 --min-free-mib 8000 -- python tacticai/train/train_multitask.py --config configs/multitask_receiver_shot_d2.yaml'"

# tmuxセッションの確認
tmux list-sessions

# tmuxセッションにアタッチ
tmux attach-session -t train_multitask_no_d2
```

### 設定ファイル

- `configs/multitask_receiver_shot_no_d2.yaml`: D2等変性無効版
- `configs/multitask_receiver_shot_d2.yaml`: D2等変性有効版
- `configs/multitask_receiver_shot_no_d2_overfit.yaml`: オーバーフィットテスト用（D2無効）
- `configs/multitask_receiver_shot_d2_overfit.yaml`: オーバーフィットテスト用（D2有効）
- `configs/multitask_receiver_shot_no_d2_overfit8.yaml`: オーバーフィットテスト用（8サンプル, D2無効）
- `configs/multitask_receiver_shot_d2_overfit8.yaml`: オーバーフィットテスト用（8サンプル, D2有効）

### 主な設定項目

```yaml
# タスクの重み（損失関数の重み付け）
multitask:
  lambda_receiver: 1.0  # 受け手予測の損失重み
  lambda_shot: 1.0      # シュート予測の損失重み

# Early stopping（受け手予測のTop-3精度を監視）
early_stopping:
  patience: 20
  min_delta: 0.0005
  monitor: "val_receiver_top3"

# 勾配クリッピング（D2有効時は0.5、無効時は1.0を推奨）
train:
  grad_clip:
    enabled: true
    max_norm: 0.5  # D2有効時
    # max_norm: 1.0  # D2無効時
```

### 出力

- ログファイル: `runs/receiver_shot/training_{timestamp}.log`
- 学習履歴: `runs/receiver_shot/training_history_{timestamp}.csv`
- ベストモデル:
  - D2有効版: `checkpoints/receiver_shot/best_d2.ckpt`
  - D2無効版: `checkpoints/receiver_shot/best_no_d2.ckpt`

### 学習の進捗確認

各エポックで以下のメトリクスが記録されます：

- **Train/Val Metrics**:
  - `total_loss`: 総合損失（receiver_loss + shot_loss）
  - `receiver_loss`: 受け手予測の損失
  - `receiver_top1`: 受け手予測のTop-1精度
  - `receiver_top3`: 受け手予測のTop-3精度
  - `shot_loss`: シュート予測の損失
  - `shot_acc`: シュート予測の精度
  - `shot_auc_roc`: シュート予測のAUC-ROC
  - `shot_f1`: シュート予測のF1スコア

### 注意事項

1. **データの準備**: 受け手予測とシュート予測の両方のデータが必要です（`data/processed_ck/receiver_*/`と`data/processed_ck/shot_*/`）
2. **D2設定**: D2有効版と無効版で別々のモデルが保存されます（`best_d2.ckpt`と`best_no_d2.ckpt`）
3. **Early stopping**: `val_receiver_top3`を監視して、patience回連続で改善がない場合に停止します
4. **メモリ使用量**: マルチタスク学習は単一タスク学習よりメモリを使用する場合があります

## シュート予測（Shot Prediction）

### データ生成

受け手予測のデータからシュート予測用のデータを生成：

```bash
python scripts/generate_shot_data_from_receiver.py
```

出力先: `data/processed_ck/shot_train/`, `data/processed_ck/shot_val/`, `data/processed_ck/shot_test/`

### 学習

```bash
# 基本コマンド（Pretrained backbone使用）
python tacticai/train/train_shot.py --config configs/shot_pretrained_backbone.yaml

# デバッグ用（過学習確認）
python tacticai/train/train_shot.py --config configs/shot_pretrained_backbone.yaml --debug-overfit
```

### 設定ファイル

- `configs/shot_pretrained_backbone.yaml`: メイン設定ファイル（Pretrained receiver backbone使用）

### 出力

- ログファイル: `runs/shot/training_{timestamp}.log`
- 学習履歴: `runs/shot/training_history_{timestamp}.csv`
- ベストモデル: `checkpoints/shot/best.ckpt`

## 生成（Tactic Generation / CVAE）

### データ生成（CKベース）

`data/processed_ck/receiver_{train,val,test}` を元に、CVAE学習用の `cvae_ck_{train,val,test}` を生成します。

```bash
python scripts/build_cvae_ck_dataset.py \
  --in-dir data/processed_ck \
  --out-dir data/processed_ck
```

出力先:
- `data/processed_ck/cvae_ck_train/data.pickle`
- `data/processed_ck/cvae_ck_val/data.pickle`
- `data/processed_ck/cvae_ck_test/data.pickle`

### 過学習テスト（1サンプル）

最初は実装の健全性確認のため、**1サンプルで過学習できるか**を確認します（train=val=testを同一にします）。

```bash
# 1サンプル（mini1）を作成
python tools/make_mini_subset.py \
  --src data/processed_ck/cvae_ck_train/data.pickle \
  --dst data/processed_ck/cvae_ck_train/mini1.pickle \
  --n 1 --seed 42

# 過学習テスト実行（D2 / no_d2）
python -m tacticai.train.train_cvae --config configs/cvae_ck_overfit1_d2.yaml
python -m tacticai.train.train_cvae --config configs/cvae_ck_overfit1_no_d2.yaml

# 最新ログをtail（別ターミナル推奨）
tail -f "$(ls -t runs/cvae_overfit_d2/training_*.log | head -n 1)"
tail -f "$(ls -t runs/cvae_overfit_no_d2/training_*.log | head -n 1)"
```

### 通常学習（全データ）

```bash
python -m tacticai.train.train_cvae --config configs/cvae_ck_d2.yaml
python -m tacticai.train.train_cvae --config configs/cvae_ck_no_d2.yaml

# 最新ログをtail（別ターミナル推奨）
tail -f "$(ls -t runs/cvae_d2/training_*.log | head -n 1)"
tail -f "$(ls -t runs/cvae_no_d2/training_*.log | head -n 1)"
```

### 生成（推論）

学習済み `best.ckpt` を読み込み、指定したサンプル（条件）から複数パターンを生成してpickleに保存します。

```bash
# D2版（checkpoint_dirから best.ckpt を自動で拾う）
python scripts/generate_cvae_samples.py \
  --config configs/cvae_ck_d2.yaml \
  --index 0 \
  --num-samples 20 \
  --denormalize

# no_d2版
python scripts/generate_cvae_samples.py \
  --config configs/cvae_ck_no_d2.yaml \
  --index 0 \
  --num-samples 20 \
  --denormalize
```

出力（デフォルト）:
- `runs/cvae_{d2,no_d2}/generated/cvae_gen_idx{index}_S{num_samples}.pkl`

### 生成結果の可視化（Streamlit）

生成pickle（上記）を読み込み、Target（GT）と生成サンプル（S本）をピッチ上に並べて表示します。

```bash
streamlit run tacticai/generation/visualization/app.py \
  --server.address 0.0.0.0 \
  --server.port 8501
```

### 出力

- ログ: `runs/cvae_{d2,no_d2}/training_YYYYMMDD_HHMMSS.log`（overfit時は `runs/cvae_overfit_{d2,no_d2}/`）
- 学習履歴: `runs/cvae_{d2,no_d2}/training_history_YYYYMMDD_HHMMSS.csv`（毎epoch上書き）
- ベストモデル: `checkpoints/cvae_{d2,no_d2}/best.ckpt`（overfit時は `checkpoints/cvae_overfit_{d2,no_d2}/best.ckpt`）

### D2 / no_d2 の使い分け（yamlを分ける）

- D2: `configs/cvae_ck_d2.yaml` / `configs/cvae_ck_overfit1_d2.yaml`
- no_d2: `configs/cvae_ck_no_d2.yaml` / `configs/cvae_ck_overfit1_no_d2.yaml`

## 類似CK検索システム（Similar CK Retrieval）

### インデックス構築

全データ（train + val + test）を使用してインデックスを構築します。

#### D2有効版の場合

```bash
python scripts/build_retrieval_index.py \
  --config configs/receiver_full_simplified_200epoch_d2.yaml \
  --output-index indices/receiver_index_d2.pkl
```

#### D2無効版の場合

```bash
python scripts/build_retrieval_index.py \
  --config configs/receiver_full_simplified_200epoch_no_d2.yaml \
  --output-index indices/receiver_index_no_d2.pkl
```

#### 特定のphaseのみをインデックス化する場合（オプション）

```bash
# Trainデータのみ
python scripts/build_retrieval_index.py \
  --config configs/receiver_full_simplified_200epoch_d2.yaml \
  --output-index indices/receiver_train_index_d2.pkl \
  --phase train

# Valデータのみ
python scripts/build_retrieval_index.py \
  --config configs/receiver_full_simplified_200epoch_d2.yaml \
  --output-index indices/receiver_val_index_d2.pkl \
  --phase val

# Testデータのみ
python scripts/build_retrieval_index.py \
  --config configs/receiver_full_simplified_200epoch_d2.yaml \
  --output-index indices/receiver_test_index_d2.pkl \
  --phase test
```

#### カスタムバックボーンチェックポイントを指定する場合

```bash
python scripts/build_retrieval_index.py \
  --config configs/receiver_full_simplified_200epoch_d2.yaml \
  --backbone-checkpoint checkpoints/receiver/custom_backbone.ckpt \
  --output-index indices/receiver_index_custom.pkl
```

### パラメータ説明

- `--config`: Receiver予測のconfigファイルを指定（D2有無は使用するバックボーンと一致させる必要がある）
- `--output-index`: 構築したインデックスの保存先パス
- `--phase`: （オプション）インデックス化するデータ分割（`train` / `val` / `test`）。指定しない場合は全データ（train+val+test）を使用
- `--backbone-checkpoint`: （オプション）バックボーンチェックポイントのパス。指定しない場合、configのD2設定に応じて自動選択される（`backbone_d2.ckpt`または`backbone_no_d2.ckpt`）
- `--use-faiss`: （オプション）Faissを使用した高速検索を有効化

**注意事項：**
- バッチサイズ、num_workersなどはconfigファイルから自動的に読み込まれます
- `--phase`を指定しない場合、train/val/testの全データを使用してインデックスを構築します
- インデックス構築には時間がかかる場合があります（データセットサイズに依存）

### 検索機能のテスト

構築したインデックスを使って類似CKを検索するテストスクリプト：

```bash
# 基本的な使用方法（trainデータの0番目のサンプルをクエリとして使用）
python scripts/test_retrieval_search.py \
  --config configs/receiver_full_simplified_200epoch_no_d2.yaml \
  --index-path indices/receiver_index_no_d2.pkl \
  --query-index 0 \
  --top-k 5

# 異なるクエリサンプルとTop-k数を指定
python scripts/test_retrieval_search.py \
  --config configs/receiver_full_simplified_200epoch_no_d2.yaml \
  --index-path indices/receiver_index_no_d2.pkl \
  --query-index 10 \
  --top-k 10

# 特定のデータファイルからクエリを読み込む
python scripts/test_retrieval_search.py \
  --config configs/receiver_full_simplified_200epoch_no_d2.yaml \
  --index-path indices/receiver_index_no_d2.pkl \
  --data-path data/processed_ck/receiver_test/data.pickle \
  --phase test \
  --query-index 0 \
  --top-k 5
```

### 検索テストスクリプトのパラメータ説明

- `--config`: Receiver予測のconfigファイル

- `--backbone-checkpoint`: （オプション）バックボーンチェックポイント。指定しない場合は自動選択

## 設定ファイルの主なオプション

### データ統合

```yaml
data:
  merge_val_to_train: true  # ValidationをTrainに統合（小データセット用）
```

### D2等変性

```yaml
d2:
  enabled: true  # D2等変性を有効化
```

### 学習設定

```yaml
train:
  batch_size: 32
  epochs: 50
  grad_clip:
    enabled: true
    max_norm: 1.0  # D2有効時は0.5を推奨
```

---

## 注意事項

1. **受け手予測の学習を先に実行**: シュート予測はpretrained receiver backboneが必要です
2. **D2設定の一致**: 受け手予測とシュート予測で`d2.enabled`を同じに設定してください
3. **データパス**: デフォルトでは`data/processed_ck/`を使用します
4. **GPUメモリ**: バッチサイズはGPUメモリに応じて調整してください

## トラブルシューティング

### メモリ不足エラー

```bash
# batch_sizeを減らす（configs/*.yamlで編集）
train:
  batch_size: 16  # 32から減らす
```

### データが見つからない

```bash
# データ生成スクリプトを実行
python scripts/generate_shot_data_from_receiver.py
```

### バックボーンが見つからない

受け手予測の学習が完了しているか確認：
```bash
ls checkpoints/receiver/backbone*.ckpt
```
