# 埋め込み多様性分析と対策

## 問題の概要

類似CK検索システムにおいて、すべての埋め込みが非常に似ている（ペアワイズコサイン距離の平均: 0.000385）という問題が発見されました。

## 分析結果

### 埋め込みの統計

- **正規化前の埋め込み**: 
  - 平均: 0.346551
  - 標準偏差: 17.684961
  - ノルムの平均: 399.82
  - ノルムの標準偏差: 18.30

- **正規化後の埋め込み**:
  - 平均: 0.000866
  - 標準偏差: 0.044186
  - ノルム: 1.0（すべて）

- **ペアワイズコサイン距離**:
  - 平均: 0.000385
  - 標準偏差: 0.000389
  - 最小: -0.000001
  - 最大: 0.001155

**⚠️ 警告**: 埋め込みが崩壊している（collapsing）。すべてのサンプルに対して非常に似た埋め込みが生成されています。

## 原因分析

### 1. タスクの不一致

- **受け手予測タスク**: ノードレベルの分類タスク（22人のプレイヤーから1人を選択）
  - グラフレベルの埋め込みは使用されない
  - モデルはグラフレベルの埋め込みの多様性を学習する必要がない

- **検索タスク**: グラフレベルの埋め込みが必要
  - 現在は平均プーリングでグラフレベルの埋め込みを生成
  - 受け手予測で学習されたバックボーンは、グラフレベルの表現の多様性を学習していない

### 2. 平均プーリングの限界

- ノードレベルの情報を平均することで、多くの情報が失われる
- すべてのグラフが似たような平均的な埋め込みに収束してしまう

### 3. 受け手予測モデルの性能

- Train Top-3 Accuracy: 0.82+
- バックボーンは適切に学習されている（ノードレベルの表現は多様）
- しかし、グラフレベルの表現は学習されていない

## 対策案

### 1. プーリング方法の変更

現在の平均プーリングから、より適切なプーリング方法に変更：

#### A. Attention-based Pooling
```python
# ノードレベルの埋め込みにAttention weightを適用
attention_weights = softmax(MLP(node_embeddings))
graph_embedding = (attention_weights * node_embeddings).sum(dim=1)
```

#### B. Set2Set Pooling
- LSTMベースのプーリング方法
- ノードの順序に依存しない集合表現を生成

#### C. Global Attention Pooling (Graph Attention Pooling)
- GATベースのアーキテクチャに合わせたプーリング

### 2. マルチタスク学習

受け手予測と検索タスクを同時に学習：

```python
# 受け手予測損失 + 検索タスクのコントラスト損失
loss = receiver_loss + contrastive_loss(embeddings, similar_pairs, dissimilar_pairs)
```

### 3. 検索専用のFine-tuning

検索タスクに対してバックボーンをFine-tuning：

```python
# 類似CKペアを正例、非類似ペアを負例として学習
# コントラスト損失を使用して埋め込みの多様性を促進
loss = contrastive_loss(embeddings_1, embeddings_2, labels)
```

### 4. 埋め込みの正則化

埋め込みの多様性を促進する正則化項を追加：

```python
# 埋め込み間の距離を最大化する正則化項
diversity_loss = -torch.mean(pairwise_distances(embeddings))
```

   - 現在のバックボーンをそのまま使用可能

### 中期
