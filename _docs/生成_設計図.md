# TacticAI: CVAE (Guided Generation) 実装設計書

## 1. 概要
本ドキュメントは、`tacticai/models/heads/generator.py` に実装する **Conditional Variational Autoencoder (CVAE)** の設計仕様を定義する。

### 目的
* **戦術生成**: 特定の条件（例：シュート成功 `Shot=1`）を満たすような、選手の最適な「動き出し（配置の修正）」を生成する。
* **摂動生成 (Perturbation)**: ゼロから配置を生成するのではなく、現在の配置からの**移動量（$\Delta x, \Delta y$）**を推論することで、学習の安定性と実用性を高める。

---

## 1.1. 本Issueで確定した前提（重要）
### 学習ターゲット（$X_{gt}$）の時刻
**$X_{gt}$ は「キックが行われた瞬間（$t=0$）」の実際の配置（位置+速度）**とする。

- **理由**: TacticAIのCVAE（Guided Generation）は「未来予測」ではなく、「ある結果（シュート等）を導くための、開始時点での最適な配置」を提案するモデルのため。

### swing / receiver の扱い
- **swing**（in-swing / out-swing / short-corner）は **条件（Condition）** とする  
- **receiver**（ターゲット受け手）も **条件（Condition）** とする  

想定ユースケース:
- コーチが「今回は**このswing**」「今回は**このreceiver**」を戦術として固定し、周囲の選手の動き出し（配置/速度）をAIに提案させる。

---

## 2. データ構造とTensor形状

### 定数定義
* `B`: バッチサイズ (Batch Size)
* `N`: 選手数 (22 = 11 Home + 11 Away)
* `D`: 入力特徴量次元 (Input Feature Dim from GATv2 output)
* `Z`: 潜在変数次元 (Latent Dim, e.g., 32 or 64)
* `C`: 条件次元 (Condition Dim, e.g., 1 for Binary Shot)

### 入出力変数

| 変数名 | 記号 | 形状 (Shape) | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| **Context** | $\overline{h}$ | `[B, N, D]` | 現在の局面のグラフ表現 | Encoder(GATv2)の出力 (Frozen) |
| **Condition** | $c$ | `[B, C]` | 条件ベクトル | 例: `shot(0/1)` + `swing(3値)` + `receiver(埋め込み)` |
| **Current State** | $X_{curr}$ | `[B, N, 4]` | 現在の選手状態 $(x, y, v_x, v_y)$ | ※残差方式を採る場合のみ使用 |
| **Ground Truth** | $X_{gt}$ | `[B, N, 4]` | **$t=0$の正解配置** $(x, y, v_x, v_y)$ | **学習時のみ使用**（観測されたキック時点） |
| **Latent** | $z$ | `[B, N, Z]` | 確率的ノイズ | 多様性を生むための潜在変数 |
| **Output (State)** | $\tilde{X}$ | `[B, N, 4]` | 生成された選手状態 $(x, y, v_x, v_y)$ | **推奨するキック開始時点の状態** |

## 3. モデルアーキテクチャ詳細

モデルは `CVAEGenerator` クラスとして実装し、以下の2つのサブネットワークを持つ。

### 3.1 Prior / Posterior Encoder (学習時のみ使用)
正解データを見て、潜在変数 $z$ の分布 $q_\phi(z|X, c)$ を学習するネットワーク。

* **入力結合**: `Concatenate([Context, GroundTruth, Condition])`
    * Conditionは `[B, 1]` → `[B, N, 1]` にBroadcastして結合。
    * GroundTruthは位置と速度を含む。
* **構造**: `MLP (Linear -> ReLU -> Linear)`
* **出力**:
    * `mu` ($\mu$): 平均 `[B, N, Z]`
    * `logvar` ($\log \sigma^2$): 対数分散 `[B, N, Z]`

### 3.2 Generator / Decoder (推論・生成用)
潜在変数と条件から、最適な移動量を生成するネットワーク。

* **入力結合**: `Concatenate([Context, Latent, Condition])`
    * Latent $z$ は、学習時はPosteriorからサンプリング、推論時は標準正規分布からサンプリング。
* **構造**: `MLP (Linear -> ReLU -> Linear)`
* **出力（本Issueの要件）**: `State` $(x, y, v_x, v_y)$ `[B, N, 4]`

---

## 3.3 重要: 「摂動生成 (Residual)」との整合性について（要確認）
本設計図の元の思想は「$\tilde{X} = X_{curr} + \Delta \tilde{X}$」の残差生成だが、
**$X_{gt}$ を $t=0$ の観測配置とする場合、$X_{curr}$ と $X_{gt}$ が同一になりやすく、$\Delta$ が常に0になって学習が崩壊**する。

よって、本Issueの現実的な実装案は以下のどちらか：

- **案A（推奨）: 絶対値生成**  
  Decoderは $\tilde{X}$（位置+速度）を直接生成し、推論時に「現状との差分」を可視化して“提案”として扱う。

- **案B: 残差生成を維持する**  
  $X_{curr}$ を「ベース配置（例：通常CKのテンプレ/平均配置/別サンプル）」として別途定義し、$X_{gt}$（shot=1のキック時点配置）へ寄せる学習ペアを作る。  
  ※この場合、データセット構築仕様（ペアの作り方）が別途必要。

## 4. 処理フロー (Algorithm)

### 4.1 学習フェーズ (`forward` with `training=True`)
1.  **入力**: $\overline{h}, c, X_{gt}$ を受け取る。
2.  **エンコード**: Posterior Encoder に通し、$\mu, \log \sigma^2$ を得る。
3.  **Reparameterization**:
    * $\epsilon \sim \mathcal{N}(0, I)$
    * $z = \mu + \epsilon \cdot e^{0.5 \log \sigma^2}$
4.  **デコード**: $\overline{h}, z, c$ を Decoder に通し、$\tilde{X}$（位置+速度）を得る。
6.  **損失計算 (Loss)**:
    * **Reconstruction Loss (MSE)**: $|| \tilde{X} - X_{gt} ||^2$
    * **KL Divergence**: $-0.5 \sum (1 + \log \sigma^2 - \mu^2 - \sigma^2)$
    * `Loss = Recon + beta * KL`

### 4.2 推論フェーズ (`forward` with `training=False`)
1.  **入力**: $\overline{h}$ (現在の状況), $c_{target}$ (こうなって欲しい結果) を受け取る。
2.  **サンプリング**: 標準正規分布から $z \sim \mathcal{N}(0, I)$ を生成。
3.  **デコード**: $\overline{h}, z, c_{target}$ を Decoder に通し、推奨状態 $\tilde{X}$ を得る。
4.  **出力**: コーチへの提案として $\tilde{X}$（位置+速度）を返す。

## 5. 将来的な拡張性 (Future Works)

本モジュールは、以下の拡張に対応できるよう設計する。

1.  **反実仮想 (Counterfactual) への接続**:
    * 現在は単純な生成だが、将来的には「もし選手Aがここに動いていたら (Intervention)」を入力とし、その後のシュート確率の変化 (Outcome) を予測する **ITE (Individual Treatment Effect)** 推定モジュールと統合する。
2.  **言語化 (Explainability)**:
    * Latent $z$ の次元に意味を持たせる（Disentanglement）、あるいは生成された $\Delta X$ の意図（例：「スペースを作る動き」）を言語モデルで記述するためのAttention機構を追加する。
