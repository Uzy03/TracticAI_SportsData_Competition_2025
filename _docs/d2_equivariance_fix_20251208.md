# D2等変性実装におけるモデル崩壊問題の調査と修正

**日付**: 2025-12-08  
**目的**: D2群対応を有効化した際のエポック30以降のモデル崩壊原因の調査と修正

## 問題の発見

D2等変性を有効化（`d2.enabled: true`）して学習を実行したところ、以下の問題が発生：

1. **エポック30以降で急激な性能悪化**
   - エポック29: Loss=2.2469, Top-3=0.4873（正常）
   - エポック30: Loss=2.2971, Top-3=0.3449（急落）
   - エポック30以降: Lossが2.31付近で停滞（学習が停止）

2. **テスト時の異常値**
   - ノード埋め込みの分散がほぼゼロ: `H_all_std=0.000123`
   - ロジット値が異常に大きい負の値: `logits_mean=-21604.330078`
   - Test性能の大幅な低下: Top-3=0.3333（ほぼランダムレベル）

## 原因の調査

### 調査プロセス

1. **デバッグログの追加**
   - GATv2Network4Viewの各レイヤー後でのNaN/Inf検出
   - 4-view平均化前後の統計監視
   - アテンションスコアの異常値検出（>50の場合に警告）

2. **ログ分析結果**
   - NaN/Infは検出されず（数値的には安定）
   - しかし、モデルの出力が異常になっている
   - エポック30前後で勾配が爆発的に大きくなっている可能性

### 原因の特定

**勾配爆発（Gradient Explosion）**

- `grad_clip.enabled: false`のため、勾配クリッピングが無効だった
- D2有効時は4-view処理により、モデルの複雑度が4倍になる
- エポック30前後で勾配が大きくなり、重みが異常に増大
- その結果、ノード埋め込みが崩壊し、ロジット値が異常になった

## 修正内容

### 1. 勾配クリッピングの有効化

`configs/receiver_full_simplified.yaml`を修正：

```yaml
train:
  grad_clip:
    enabled: true  # false から変更
    max_norm: 1.0  # 勾配の最大ノルムを1.0にクリッピング
```

### 2. デバッグ機能の追加

`tacticai/models/gatv2.py`に以下を追加：

- 各レイヤー後でのNaN/Inf検出ログ
- Residual接続後、活性化後、LayerNorm後の統計監視
- エポック30前後での詳細統計ログ（エポック番号追跡機能）

`tacticai/train/train_receiver.py`に以下を追加：

- 4-view平均化前後のNaN/Inf検出ログ
- 各viewの統計情報

## 修正後の結果

### 学習の安定性

**修正前（勾配クリッピング無効）:**
- エポック30で学習が停止
- Loss=2.31付近で停滞

**修正後（勾配クリッピング有効）:**
- エポック30以降も学習が継続
- Loss=1.94まで改善
- Best Train Top-3=0.5728

### テスト性能の改善

**修正前:**
- `H_all_std=0.000123`（埋め込み崩壊）
- `logits_mean=-21604.330078`（異常値）
- Test Top-3=0.3333

**修正後:**
- `H_all_std=0.013844`（正常範囲）
- `logits_mean=17312.548828`（大きいが、分散あり）
- Test Top-3=0.4386（+10.5ポイント向上）

### D2有効/無効の性能比較（2025-12-08時点）

| 設定 | Train Top-3 (Best) | Test Top-1 | Test Top-3 | Test Top-5 |
|------|-------------------|------------|------------|------------|
| D2無効 + grad_clip無効 | 0.5570 | 0.2807 | **0.4737** | 0.5789 |
| D2有効 + grad_clip有効 | 0.5728 | 0.2632 | 0.4386 | **0.5965** |

**所見:**
- D2有効時はTrain性能が高いが、Test性能はD2無効よりやや低い（-3.5ポイント）
- これはD2有効時の過学習の可能性を示唆
- ただし、勾配クリッピングにより、モデル崩壊の問題は解決

## 今後の検討事項

1. **D2有効時の性能向上**
   - 正則化の追加（dropout、weight_decayなど）
   - 学習率の調整
   - より適切な初期化

2. **ロジット値の正規化**
   - 現在、ロジット値が依然として大きい（17312）
   - 出力層のスケーリングを検討

3. **公平な性能比較**
   - 同じ設定（`grad_clip.enabled: true`）でD2有効/無効の両方を再実行
   - より厳密な比較を行う

## 結論

**主要な成果:**
- D2有効時のモデル崩壊原因（勾配爆発）を特定
- 勾配クリッピングの有効化により問題を解決
- エポック30以降も学習が継続し、性能が向上

**現時点での推奨:**
- D2無効の方がTest性能で優位（Top-3: 0.4737 vs 0.4386）
- ただし、勾配クリッピングにより、D2有効時の学習は安定化
- さらなる調整により、D2有効時の性能向上の余地がある
